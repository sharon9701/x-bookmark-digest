# Annotation contract

`pending` 输出一个 JSON 对象，包含 `generated_at`、`since`、`until`、`window`、`target_date`、`timezone`、`claimed`、`diagnostics` 和 `items`。每日模式的 `window` 为 `previous_day`，`target_date` 是配置时区下的上一自然日；默认按本地 `first_seen_at` 作为新增代理。AI 处理每个 item 后，必须保留输入中的 `id`、`url`、`author`、`title`、`text`、`sources`、`media_urls`、`first_seen_at`，并增加或更新：

```json
{
  "id": "tweet id",
  "category": "工具与产品",
  "secondary_category": null,
  "confidence": 0.86,
  "summary": "一句话 TL;DR",
  "key_points": ["要点 1", "要点 2"],
  "recommended_action": "今天阅读并试用仓库",
  "priority": 1
}
```

## 分类决策

- `category` 必须来自当前配置文件 `categories` 中的名称，或使用 `待复核`；不要假设某一套固定分类。
- 先根据正文、引用上下文、链接标题和媒体说明判断主题，再选择证据最充分的主分类。
- 多类证据接近时，按当前配置文件中的分类顺序决胜；只有第二主题有独立、具体证据时才填写 `secondary_category`，不要为了完整而凑双分类。
- `confidence` 是 0–1 的数值，反映对主分类的把握，不是内容质量评分。低于 0.6 时必须把主分类改成 `待复核`。
- `priority` 只表示阅读顺序：1=今天优先，2=本周阅读，3=长期存档。已进入书签或喜欢/点赞栏的内容不需要再证明“值得读”。
- 人工用 `mark --category` 指定的分类优先于 AI 分类；AI 只提供建议，不回写或覆盖人工决策。

## 摘要决策

- `summary` 是不超过 80 个字符的一句话 TL;DR；不要复制整段原文，不要写“为什么值得读”。
- `key_points` 默认写 4–6 条，长文、文章或线程可写 6–8 条；只有短链接或正文极少时才少于 4 条。所有要点合计不超过 200 个字符（去除空白后计算）；每条写一个可验证的事实、方法、数据、上下文或限制；不要把作者的推测写成事实，也不要用同义句重复摘要。
- `recommended_action` 必须存在并以动词开头，例如“阅读并试用”“加入项目”“跳过并归档”。
- 投资、股票和市场内容的要点中必须加“仅供研究，不是投资建议”。
- 媒体-only、引用推文、文章、线程、已删除或受保护内容：只写可见证据，明确说明缺失信息；无法可靠判断时使用 `待复核`。

## 标题和媒体

- `title` 优先使用 X 返回的文章标题；普通推文没有正式标题时，保留原贴第一行或第一句，不要由 AI 改写成营销标题。完全没有正文时使用“原贴未提供标题”。
- `media_urls` 中的图片全部保留；卡片优先展示第一张，其余作为缩略图或媒体链接。视频不强行当作图片，提供播放/打开媒体链接；任何预览失败都必须保留原帖链接作为回退。

`render` 会拒绝以下结果：缺少 `id`、分类不在允许集合、次分类非法、置信度不在 0–1、低置信度却未标 `待复核`、摘要为空或超过 80 字符、要点不是最多八条字符串、要点合计超过 200 个字符、没有建议动作、优先级不是 1/2/3、或出现重复 ID。失败时不生成 Markdown。

## 卡片交互

卡片由渲染器补充队列位置和进度，不在注释 JSON 中重复维护。支持 `single` 和 `batch` 两种模式；默认 batch 每组 3 条，短内容可用 5 条。顶部必须先输出截图风格的原生 Markdown 步骤卡片：

```text
> `━━━━ ○ ○ ○ ○`  `▶`
> **Step 1 of 32**
```

五格只负责紧凑表达相对进度，`Step n of N` 才是真实队列位置；`▶` 是视觉上的继续标记，不是按钮，也不触发输入框。卡片只允许四个动作：`1`=read 并移出当前来源，`2`=keep，`3`=纳入 Obsidian，`4 <分类>`=调整分类。single 模式在选择完成后显示下一张卡片；batch 模式按顺序处理一组决定后显示下一组。不要用 HTML 或 `request_user_input` 替代这套 Markdown 交互。
